## Findings

### Important
1. DisplayCard.xaml (Style.Text.ActionBar.LayoutLabel DataTrigger on HasDraft): the label collapses on HasDraft alone, not on available width. On a 613 px (or any wider) card that has plenty of room, a draft still turns "More layouts" into an icon, and the Layout button shrinks by ~100 px while the DraftChip appears/disappears, so Copy layout and the chip jump left/right on every draft toggle. The controller ruling covers the 400 px minimum; it does not cover wide cards. No test checks a wide card with a draft (ActionBar_FitsA400pxCard only runs at 400; the 613 draft cases are not asserted for the label). Suggest a width-driven switch (SizeChanged on the dock or a converter on the dock's ActualWidth) or at least a test that documents that wide cards also collapse.
2. GridSpec.DisplayCard still has MinCardWidth = 320 (AdaptiveGridLayout.cs:28, 40) and non-carousel grid plans (lines 84, 105-108) can still produce 320-399 px display cards. The implementer states the bar needs about 350 px, so the bar clips there (power pushed out, or labels cut). The tests moved from Size.Card.Min to 400 and no longer guard this range. If grid mode is still reachable for display cards this is a regression; if it is not, there should be a test or assertion that says so (for example DisplayCard spec MinCardWidth >= 400).
3. Weakened coverage in ViewSmokeTests.UiV2SegmentedPresets.cs: `LayoutSegments_HaveOneOutline_AndNoSegmentBorder` and `LayoutSegments_HoldTheLayoutDropdown_AsOneSegment_...` were deleted. The segment is gone so the intent is replaced, and the new `LayoutButton_HasNoFillOrOutline_AtRest_AndNoSegmentGroup` (UiV2LayoutButton) and `ActionBar_LayoutAndCopy_ShareHeightAndPadding` cover the same ground (no group, no fill, no outline, 48 high). Acceptable, but note the replacement "no visible bordered child" check only runs at rest and not for hover/pressed/focus. `ActionBar_FitsA400pxCard_AtEveryDpi` also skips collapsed labels via IsVisible, which hides a label that collapses for the wrong reason (see 1).

### Minor
4. 150 % DPI test (UiV2ActionBar.cs, `host.LayoutTransform = new ScaleTransform(1.5, 1.5)`): WPF lays out in DIPs, so the result is identical to 100 % and the Theory proves nothing about DPI. Feasible improvements: set `TextOptions.TextFormattingMode`/`UseLayoutRounding` and measure under a larger system-font scale (`FontSize` x 1.25/1.5 as a text-scaling test, which does stress the 374 px budget with only about 27 px slack), or rename the case "scaled host" so it is not claimed as DPI coverage. Real per-monitor DPI needs a manual or screenshot check (Task 5).
5. The fit tests do measure the real DisplayCardView through `rig.View(..., 400)` and `FloatingActionDock`, not a fake host. The slack is thin: no-draft bar needs ~347-350 of 374 px; a font or ClearType change or a longer localisation will clip. Consider a margin assertion (remaining space >= N px) so a creeping label is caught.
6. Dead now (Minor, not removed): `Style.Icon.Button`, `Style.Icon.Button.Stroke`, `Style.Icon.Power` (DisplayCard.xaml:44-61, only referenced by each other), geometries `Icon.Power` (still asserted by TestResourcesTests.cs:106), `Icon.Grid`, `Icon.Copy`, tokens `Size.Layout.Button.Width/Height` and `Size.Icon.Layout.Chevron` (only UiV2TokenTests.cs:37 uses them). The Tokens.xaml comment at lines 20-22 still describes the 64 x 56 Layout button and Style.Icon.Button. Clean up in a later task and update UiV2TokenTests/TestResourcesTests with it. UiV2StylesTests.cs:338 comment still names Style.Button.CopyLayout.
7. CopyIcon and LayoutIcon dropped HorizontalAlignment; fine. TurnOffButton hover: Foreground is a local value (Primary), so the Ghost hover colour change no longer applies (icon stays Primary on hover); harmless, but the ghost hover fill is the only hover cue.
8. Copy "nothing to copy" dims the whole button including the hover fill (Opacity on the control), while the disabled path dims only Root; equivalent visually.
9. `CopyLayout_WhenThereIsNothingToCopy...` now asserts button.Opacity instead of the template root: correct for the new design, not weakened.
